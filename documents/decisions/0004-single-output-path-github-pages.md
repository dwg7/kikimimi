# ADR 0004: 出力経路をGitHub Pagesへの一本化に限定する

- 状態: Accepted (2026-09-16)
- 文脈タグ: 運用, UI

## 背景

kaga0では、RPi上でWebサーバーとブラウザ(キオスクモード含む)を同時に
動かす構成のノウハウが蓄積されている。kikimimiでも同様の「現場での
air-gapped表示」を検討する余地はあった。

## 決定

kaga0のノウハウは、このプロジェクトでは転用しない。RPiの役割は
**キャプチャ+文字起こしに徹する**、という境界を明確にする。

- RPi 4Bの仕事は、RTL-SDRでの録音とwhisper.cppでの文字起こしまで。
  結果はMac miniへ送るだけで完結し、RPi自身が何かを表示することはない
- Open MCTダッシュボードは、`stars`と同じ方式でGitHub Pagesへプッシュし、
  必要な人が必要な端末(Mac、ブラウザのある任意の端末)から見る、
  という単一の経路に絞る

## 検討した代替案

- **kaga0と同じ構成(RPi上でWebサーバー+ブラウザ同時稼働)を転用する**:
  却下。理由を問わず採らない、という判断そのものが決定であり、
  「RPiは表示を担わない」という境界の明確さを優先する
- **現場でのair-gapped表示**: 却下(今回のスコープからは外す)。
  将来必要になった場合は、改めて別の手段(kaga0とは別の設計)を
  検討する。積雪期の長期対応が見込まれる十勝岳の状況次第では、
  再検討の余地がある

## 影響

出力経路が1本(GitHub Pages)に絞られることで、RPi側の運用がシンプルに
なり、障害点が減る。一方で、現場(登山口、避難所等)での直接閲覧が
必要になった場合は、このADRを見直す必要がある。
