# ADR 0019: `ja-radio-disaster`の判定結果を、ダッシュボードの参考パネルとして公開する

- 状態: Accepted (2026-09-21)
- 文脈タグ: Open MCT, 公開, レンズ

## 背景

[ADR 0018](0018-parallel-validation-lens.md)で`ja-radio-disaster`
(gate.txtを持たない、OpenSpeechMap本体付属のレンズ)を独立タイマーで
並行稼働させ、「`tokachi-lens`が0件を続けているのは判定経路の不調では
なく実際に対象事象が無いためだ」という裏付けを得ることに成功した。
実機検証(1373件処理、35件がis_disaster=trueと判定)では、台風25号の
実際の報道時間帯に正しく反応することを確認済みで、その時点では
「検証用シグナルであり、`docs/`の外に出力し公開経路に含めない」という
慎重な扱いにしていた。

その後の運用で、この判定結果自体(台風・大雨・暴風の注意報/警報関連の
話題を検出できている)が、ユーザーにとって単独でも有用な情報だと
判断された。「ダッシュボードに出す情報を増やせないか、注意報・警報の
パネルを追加したい」との要望を受け、この検証用シグナルを正式に
ダッシュボードの参考パネルへ昇格させる。

## 決定

`scripts/lens-to-openmct.sh`を汎用化し(判定フィールド名・出力ファイル名を
引数化。既存の`tokachi-lens`呼び出しは無引数側のデフォルト値で従来通り
動作)、`scripts/run-disaster-lens.sh`の各tick(10分間隔)の最後で
`docs/data/live-disaster.json`を書き出すようにする。
`kikimimi-provider.js`に「注意報・警報など(参考シグナル)」パネルを追加し、
直近20件のイベントを表示する。`scripts/publish-live-data.sh`の
git add/commit対象にも`docs/data/live-disaster.json`を加え、既存の
`live.json`・`health.json`と同じ30分周期で自動公開されるようにする。

### 「参考シグナル」であることを明示する

`tokachi-lens`本体の検出条件(gate.txtで十勝岳関連キーワードに限定)より
遥かに広く反応するレンズであるため、ノイズ(無関係な話題の誤検出。
実測で大相撲の結果が1件混入した例あり)を含むことをパネルの説明文に
明記する。件数も直近20件に絞り、際限なく伸び続ける表を避ける。

`kikimimi-root.md`([CLAUDE.md](../../CLAUDE.md)冒頭)の「verified
intelligenceではない、状況認識のための補助的なsignal」という留保は、
このパネルにより一層強く当てはまる——`tokachi-lens`より判定基準が緩い分、
参考情報としての位置づけを一段弱めて示す必要がある。

### 公開判断の経緯

[CLAUDE.md](../../CLAUDE.md)4節の標準的な作業分担では「公開する検出結果・
抜粋の内容確認は、特に稼働初期は人が一度目を通してから公開する」と
定めている。今回はユーザー自身が「パネルを加えて、pushまでいきたい」と
明示的に依頼しており、かつ本ADR作成と同じやり取りの中で実際の判定結果
(台風関連の話題が中心、十勝岳関連は無し)を確認済みである。これを
もって、この最初の公開についての人間によるレビューを満たすものとする。

## 検討した代替案

- **新しい専用レンズ(注意報・警報に絞ったgate.txt付き)を新設する**:
  却下(今回は見送り)。`ja-radio-disaster`は既にOpenSpeechMap本体が
  実績を持つレンズであり、`tokachi-lens`のように「検出条件そのものを
  新規に設計し人間が最終確認する」プロセスを経ずに、既存の検証済み
  資産をそのまま再利用できる。新規レンズの設計・レビューは、この
  参考パネルの有用性が実際に確認できてから改めて検討する
- **頻度プロット(series)も含めて完全にtokachi-lensパネルと同じ構成にする**:
  見送り。まずはイベント一覧のみのシンプルな構成で様子を見る
  (`lens-to-openmct.sh`自体はseries計算も汎用化済みなので、必要になれば
  同じ関数呼び出しで拡張できる)

## 影響

- `docs/data/live-disaster.json`が新たに一般公開される(直近20件の
  イベント、`t`・`text`・`category`・`topic`を含む。放送内容の抜粋である
  ことに変わりはないため、既存の`live.json`と同水準の扱い)
- `run-disaster-lens.sh`の10分間隔の各tickごとにファイルが更新され、
  `publish-live-data.sh`の30分周期でGitHub Pagesへ反映される
