# ADR 0014: kikimimiの用途では「ワンセグチューナーで十分」——yuisekiさんの助言と実測の整合

- 状態: Accepted (2026-09-20)
- 文脈タグ: ハードウェア, 対象局選定

## 背景

[追跡issue](https://github.com/unopengis/7/issues/1008)で、yuisekiさん
(OpenSpeechMap開発者)から以下のコメントがあった。

> - SDR は以下で十分です
>   - https://www.amazon.co.jp/gp/product/B008H8JA9O/
>   - ワンセグ用と書いてありますが、FM放送もいけます。復調はOSSライブラリでできます
> - いわゆる HackRF や RTL-SDR ブログ 的なものはオーバースペックです

この助言自体は疑っていないが(ピアの技術的主張は独立に裏取りする、という
[CLAUDE.md](../../CLAUDE.md)の方針を踏まえても)、2026-09-19〜20の2日間、
RTL-SDR Blog V4を実際に触り倒した(アンテナ調整・ゲイン最適化・AM受信
検証・GNSS検討・個体のPPM較正)結果を踏まえて、**どういう意味で
「十分」なのかを具体的に裏取り・整理する**。

## 調査

紹介された製品(ゾックス DS-DT310BK、「USBワンセグチューナー+FMラジオ」)
の実態を調べたところ、以下が分かった。

- **DS-DT310BKは`RTL2832U`チップセットを搭載している**——これは
  RTL-SDR Blog V4の核心部品と**全く同じ**チップである
  ([DS-DTシリーズ RTL2832U搭載モデル SDR(ソフトウェアラジオ)](https://shattered-blog.com/archives/4189))
- RTL2832Uドライバを導入すれば、50MHz〜1700MHzの受信、FM(狭帯域/広帯域)・
  ステレオ・AM・SSBの復調が可能——**そもそも「RTL-SDR」という
  ホビイスト界隈自体が、この種の安価な地デジ/ワンセグ用USBチューナーを
  ハックしてSDRとして転用したことから始まっている**(この事実は
  今回初めて明示的に確認した)
- つまりyuisekiさんの助言は比喩や単純化ではなく、**文字通り同じ核心
  チップを積んだ製品を指している**

## 整理:RTL-SDR Blog V4の「上乗せ分」は、kikimimiでは何一つ効いていない

2日間の実機作業で使った・調べたV4固有の機能を棚卸しし、それぞれが
kikimimiの実運用でどう効いたかを整理する。

| V4の上乗せ機能 | 今回の実際の効き方 |
|---|---|
| R828Dチューナー(高感度・低雑音) | **効いていない**。85.2MHz NHK-FM北海道は終始強い信号で、[ADR 0009](0009-rpi-os-trixie-cloudinit-just.md)のゲインスイープでは**感度不足ではなく過負荷(オーバーロード)が問題**になった。最適ゲインは最大49.6dBに対し20.7〜33.8dBと、余裕を持て余していた |
| 1PPM TCXO(高精度発振器) | **効いていない**。200kHz間隔のFMチャンネル・±75kHz偏移に対し、無補償の水晶発振子でも数十〜150ppm(85MHzで数kHz)程度のズレに収まり、音声・文字起こしの品質には無関係。今回わざわざ20分かけて個体のPPM([-0.84ppm](0009-rpi-os-trixie-cloudinit-just.md))を測ったのは、GNSS的な精密用途への興味からであり、kikimimi本体には不要な精度だった |
| バイアスティー(GPS等アクティブアンテナ給電) | **使っていない**。GNSS受信は[ADR](0013-stay-on-fm-am-switch-rejected.md)で検討したが、「このハードウェアでは面白くない」として見送った |
| HF/中波のダイレクトサンプリング不要設計 | **恩恵なし**。AM(567kHz)受信は[ADR 0013](0013-stay-on-fm-am-switch-rejected.md)の通り、受動ロッドアンテナの限界で断念しており、V4の中波対応の良し悪し以前の話だった |
| 金属シールドケース・高品質コネクタ | **恩恵は間接的**。実際に一日格闘したノイズ問題(送電線疑惑、ワイヤレストラックボールのドングル)は、いずれもアンテナ側・周辺機器側の話で、受信機自体のシールドで解決したわけではない |

## 決定

**kikimimiの用途(既知の固定周波数・強い地元局のFM放送を受信し、
音声認識でテキスト化する)においては、RTL2832Uチップを積んだ
安価なワンセグチューナーで十分であり、RTL-SDR Blog V4のような
専用SDR機材はオーバースペックである、というyuisekiさんの助言を
実測に基づいて確認・追認する。**

今回V4を選んだこと自体を後悔する話ではない——`rtl_power`による
定量的な信号強度・ノイズフロア測定、AM/GNSS/PPM較正といった
探索的な検証は、V4の追加機能(高感度・TCXO・バイアスティー)が
あったからこそ気軽に試せた側面がある。しかし**それらの探索の結論は
軒並み「kikimimiの本筋には不要」だった**、という点が今回の整理の
要点である。

## 影響

- 今後、RPi実機のRTL-SDRが故障・交換が必要になった場合、**同等品の
  RTL-SDR Blog V4を買い直す必要は無く、RTL2832Uベースの安価な
  ワンセグチューナー(ゾックスDS-DTシリーズ等)で代替可能**という
  選択肢を持てる
- この知見は、他のdwg7プロジェクトで同様の「固定・既知の強い放送を
  ラジオで拾う」用途がある場合にも転用できる可能性がある。運用実績が
  積もったらcafebabeへの書き戻しを検討する([CLAUDE.md](../../CLAUDE.md)3節の慣習)
- 逆に言えば、**V4の追加投資が正当化されるのは、GNSS・弱い/遠い局の
  DX受信・HF受信といった、kikimimiが実際には必要としない用途に
  踏み込む場合**である、という境界線も今回の探索で明確になった

## 検討した代替案

特になし。今回は「既に持っている機材の性能を、実際の用途に照らして
検証・整理する」という振り返り的なADRであり、機材変更の決定は伴わない。
